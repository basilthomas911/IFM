## Identity and contracts

`IMarketDataApi.GetTradeStrategySymbolsAsync(TradeStrategyFamilyType family, CancellationToken)` returns `ServiceResult<TradeStrategySymbolReadModel[]>`. MessagePack keys are 0 Id, 1 Symbol, 2 Currency, 3 Exchange, 4 Description. Every returned item requires a positive ID, nonempty trimmed Symbol/Exchange, a three-uppercase-letter Currency and generated Description such as `ES futures` or `ES futures options`. A bad item fails the entire lookup; no partial success, fabricated currency/exchange, or stale-cache fallback is returned.

The stable IFM product identity is the sequence-allocated integer associated with `(Family, Exchange, Symbol, Currency)`. Example: FuturesOption / XCME / ES / USD. Exchange is provider metadata, not a hard-coded spelling guarantee. Identity survives application restart and futures contract rollover; it is not a Databento expiring instrument ID. Different families, exchanges, symbols or currencies produce different IDs. Sequence gaps from competing writers are acceptable; IDs are never reused.

`TradeStrategyFamilyReadModel` retains keys 0–11 and appends key 12 TradeStrategySymbolId and key 13 Exchange. `SystemKey` is exactly the enum-name composition `Family-Strategy` (e.g. `FuturesOption-VerticalSpread`). It is classification, NOT unique identity. Several definitions can share it. The exact family reference is `(TradeStrategyFamilyId, DefinitionVersion)`. New definitions start Active at version 1. Change appends the next version under the same family ID; Remove appends a Retired version. Previously stored exact versions are preserved. Natural duplicates `(Family, Strategy, TradeStrategySymbolId, TimeFrame)` are rejected among current active definitions. Change/Remove require the selected exact version and reject stale edits.

## Provider boundary and configuration

`GetTradeStrategySymbols(family)` now reads the active ReferenceDb instrument-definition snapshot. It does not download Databento data, scan all instrument rows, or allocate product IDs. `StoredInstrumentDefinitionSymbolCatalog` reads the current snapshot and the small family product index. No five-minute query cache hides a newly published refresh. Futures and FuturesOption are supported; unsupported families fail before database access. If no completed snapshot exists, the query returns an explicit unavailable result.

`InstrumentDefinitionRefresh.RefreshAsync` is the reusable on-demand import operation. It streams `ALL_SYMBOLS`, schema `definition`, for each configured `AppSettings:Databento:TradeStrategySymbolDatasets` dataset (currently `GLBX.MDP3`; an empty list uses the configured feed dataset). The request starts at midnight on the day preceding the provider's latest available definition date and ends at that schema's reported availability boundary. It is a current reference snapshot, not a download of all historical definitions.

Each provider JSON line is retained unchanged, including the header, integer nanosecond timestamps, fixed-point prices, undefined-value sentinels, spread/leg fields, and fields the application does not currently interpret. Every returned record is stored, including definition updates; the load does not discard non-futures records. Indexed columns expose dataset, publisher, instrument ID, raw symbol, asset, class, currency and exchange. A per-dataset record index distinguishes successive records and spreads across 128 Scylla partitions. This replaces the previous lossy `ContractDetail` projection as the persistence format.

The product index uses the latest record per publisher/raw symbol, removes deleted and expired instruments, and groups distinct `(Family, Symbol, Exchange, Currency)` products. Futures use their asset/root. Options join to a unique current outright future by publisher plus `underlying_id`; exact underlying symbol is used only when the ID is absent. Option roots are not assumed to equal futures roots. Incomplete metadata and unresolved underlyings do not create selectable products, but their full raw definitions remain stored. Product IDs are obtained from the existing `trade_strategy_symbol_v1` store during refresh, so saved family references keep their identities.

A refresh writes a new snapshot and its complete product index before changing the active snapshot pointer. Failure or cancellation leaves the previous completed snapshot active; a first failed load leaves the query unavailable. Snapshots, including interrupted loads, are retained for now; automated scheduling and retention/cleanup are future work. The importer has bounded concurrent database writes and caller cancellation, and the maintenance command imposes a 30-minute overall deadline. No daily startup reload, hosted background service or scheduled task is registered.

Run the explicit maintenance command from the API Server project directory using the intended environment/configuration:

```powershell
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet run --project . --no-launch-profile -- --refresh-instrument-definitions-only
```

Development targets the configured `reference_test_db`; Production uses its own configured ReferenceDb. The command creates only the three definition tables and the existing symbol identity table if missing, then imports and verifies both family queries. It uses the configured PostgreSQL sequence allocator for new symbol IDs. It starts no HTTP server, NATS actors, live feeds or scheduler, and needs no Redis connection. `DATABENTO_API_KEY`, provider definition access, Scylla and the existing sequence database are required. The normal API startup creates the schema idempotently but does not refresh data. `--verify-startup-only` retains precedence and does not populate tables.

## Commands, queries and UI

References > `trade strategy families` uses the Lookup Type-style list/detail layout. Family lists distinct enum values; Strategy lists the latest active version of each definition in the selected family. When strategy names repeat, entries display `strategy-symbol-currency-timeframe exchange`. Details appear directly on the right, with each caption aligned to its field's first text line. Inputs use black backgrounds, white text and Microsoft Sans Serif 10pt.

**Add** opens inline creation. **Change** loads the selected definition into the same editor and turns the Change button into **Save**. Family, Symbol, Strategy, TimeFrame and multiline Description are editable; Currency, Exchange and SystemKey are derived. **Cancel** discards the draft without a write. **Remove** asks `Remove strategy-symbol-currency-timeframe exchange ?` in a Yes/No message box with `MessageBoxIcon.Question` and No as the default. Only Yes sends the command. Success reloads the list and hides the retired definition. Failures retain the selected row or edit draft for retry. Buttons, selection and close are fenced while commands are pending. Import remains disabled.

Select Futures/FuturesOption, a supported strategy, Daily/Weekly/Monthly, and a returned **Symbol**. Family selection queries market metadata; a single returned symbol is automatically selected. Symbol selection populates read-only Currency and Exchange; SystemKey is generated. Description is suggested from the selected record and remains editable (1–512 characters), with the same black background/white foreground as Exchange. Custom description text is not overwritten by subsequent symbol/family selection. A family change clears symbol metadata; generation fencing prevents delayed results from replacing a newer selection. Loading, invalid metadata and failures block creation. Failed saves retain the draft and stable retry operation ID. References selector labels are `trade strategy families` and `economic calendar definitions`; the latter still routes by the existing EconomicCalendar short code, without modifying stored lookup definitions.

UI query path: `MarketDataQueryService.GetTradeStrategySymbolsAsync` → `IMarketDataQueryApi.GetTradeStrategySymbolsAsync` → MarketData.Shared `GetTradeStrategySymbolsQuery` → MarketDataQueryActor → `IMarketDataApi.GetTradeStrategySymbolsAsync`. The Market Data read model already supplies Id, Symbol, Currency, Exchange and Description; no duplicate product identity/model is introduced. The old Reference symbol query remains compatible for older clients but the family editor no longer uses it. NATS and HTTP clients both expose the new Market Data query; HTTP is `GET /api/marketdata/trade-strategy-symbols?family=FuturesOption`. Create, Change and Remove use the corresponding `IReferenceCommandApi` methods and typed commands through the NATS client, TradeStrategyFamilyCommandActor, TradeStrategyFamilyCreationService and catalog store. No UI accesses Databento or ReferenceDb directly.

`TradeStrategyFamilyType` now resides in the common Shared assembly to avoid a MarketData.Shared ↔ Reference.Shared dependency cycle. Its public namespace and numeric values are unchanged; Reference.Shared forwards the original type for compatibility. Storage keys, IDs and existing MessagePack field numbers are unchanged. Deploy/rebuild API and UI together for the new route; changing routing does not bypass missing provider credentials, unsupported families, incomplete definitions or persistence failures.

The request contains OperationId, Family, Strategy, TimeFrame, TradeStrategySymbolId and Description. It does not accept a client family ID, Symbol, Currency or Exchange. The service verifies the selected product against the current catalog and derives stored metadata. Audit time is server UTC; creator follows the existing command transport's server-account identity convention (not a new authenticated end-user identity mechanism). The command returns its operation acknowledgement; the UI reloads the authoritative list after success.

Retries retain the same OperationId for the same request. One database compare-and-set transaction records both definition and receipt. Replaying a committed request returns the same ID/audit record; reuse with different content or a new-operation natural duplicate fails. Unknown outcomes may be retried safely. Create and Change validate the product against the stored symbol catalog before consulting the receipt. Remove does not require symbol discovery. Change and Remove append version/operation receipts to the same CAS document; concurrent edits of the same expected version cannot both commit.

## Storage and rollout

Normal Reference schema startup adds these tables without replacing legacy tables:

- `trade_strategy_symbol_v1`: partition family; clustering exchange, symbol, currency; persistent integer id. Conditional insert establishes the winner.
- `trade_strategy_family_catalog_v4`: one `V1` catalog partition containing revision and `payload_json`; a conditional revision update atomically owns entries, natural keys and operation receipts. Create/Change stop adding entries at 1,000 catalog entries; retirement remains available at that limit. Each command allows 16 contention attempts. This is a small administration catalog, not an instrument-level chain store.

Symbol IDs use the appended `Reference_TradeStrategySymbolId` sequence; family IDs use existing `Reference_TradeStrategyFamilyId`. Normal sequence initialization provisions enum-named sequences. Production sequence provisioning is unchanged; real CQL concurrency tests substitute only the sequence allocator.

Family queries combine preserved v3 seeds with all v4 definition versions and retirement records. Current UI choices select the highest version per ID before filtering for Active, while exact historical references remain queryable. Bootstrap recognizes the original seed version and does not resurrect retired seeds. The old v2→v3 migration preserves existing IDs, versions and audit data. The three canonical ES seeds remain unlinked legacy definitions with TradeStrategySymbolId=0 and empty Exchange; no guessed Exchange is written. They remain queryable/selectable by exact family identity. **All new product-linked definitions and all symbol lookup results require populated Symbol/Currency/Exchange.** A newly created linked definition may share classification with a legacy seed; it has its own exact ID. Existing policy references are not rewritten.

Fund mandates append MessagePack key 21 `PermittedTradeStrategyFamilies` (array of exact ID/version references). Assignments append key 22 `TradeStrategyFamily`; combined reference query rows append key 17. Updated editors write SchemaVersion 2. Existing string fields remain classification mirrors/legacy compatibility, not authority for typed mandates. Fund events, snapshots and JSON read projections carry the appended fields; their existing payload-based storage needs no table replacement. Exact-reference mandates cannot downgrade to legacy name-only permissions. The server validates that new references target the latest active catalog version and matching classification; assignment acceptance verifies exact Fund membership.

Legacy records are not bulk-rewritten. In editors, a name-only reference resolves only when exactly one active definition matches; otherwise it remains unavailable until explicitly replaced. Pre-v2 commands retain the preexisting legacy compatibility path; integrations should migrate to SchemaVersion 2. Typed Funds cannot accept a name-only assignment. Neither product discovery nor catalog creation automatically enables a family for any Fund.

Deploy matching API/UI binaries together; start the API with normal additive schema/bootstrap initialization before reconnecting the UI. Do not mix older seven-key family payloads with the typed layout or downgrade after creating exact references without reviewing those records. The source change does not restart the running application or migrate its live tables. Back up ReferenceDb plus sequences using normal operational procedures; restoring one without the other risks identity conflicts.
