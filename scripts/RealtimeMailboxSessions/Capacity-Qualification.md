# Capacity admission

`capacity_tool.py --plan capacity-plan.json --refresh-measurements --refreshed-plan-output <new-plan.json> --output <new-report.json>` performs read-only admission. The controller calls `refresh_measurements(plan)` then `evaluate(plan)` immediately before each phase. Refresh reads actual PostgreSQL/Scylla sizes, inspected container IDs, bounded owner-root inventories and fresh Docker guest free space; updating a timestamp alone is insufficient. Source growth beyond the fixed snapshot/restore budgets is rejected. The tool does not preallocate space, delete evidence or activate transport.

Every volume retains32GiB headroom in addition to its reservation. The archive budget uses128GiB bodies+16GiB receipts+approximately5.2GiB derived receipt index, rounded to150GiB for each original/recovered copy. Memory and File restores run sequentially and read the same verified immutable copied archive; a third full source-body copy is not budgeted or permitted in that mode. Each replay retains32GiB limits separately for full-source and destination receipts, plus derived indexes. Actual owner files, the separate initial archive-floor copy and duplicate restored native prefixes are summed before checking the32-GiB working limit; it is not a32-GiB allowance per copy. Every phase includes retained earlier artifacts.
