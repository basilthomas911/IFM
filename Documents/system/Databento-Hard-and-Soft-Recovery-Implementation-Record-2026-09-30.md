### DHR-00 source inventory (2026-09-30)

| Surface | Current entry point and dependency | Characterization needed |

Current dependency path: live-pipeline/publisher detectors → watchdog serialization → status probe and PostgreSQL observation → supervised runtime stop (owned workers, host publisher) → contract-authority reconciliation (database) → host publisher start → per-dataset child start → native/local probe → PostgreSQL observation and status publication. The isolated hard-runtime path replaces only a test/composition seam so far; it is not the production path. The plan's DHR-00 exit also requires retained failing characterization tests and a successful replacement timing baseline. Neither has yet been established for this inventory, so DHR-00 remains open.

Existing characterization evidence: `DatabentoResiliencyTests.Exhausted_core_failure_runs_exactly_three_serial_recovery_attempts_and_latches_red` proves the legacy watchdog's local three-attempt/Failed behavior; `Manual_and_automatic_operations_share_one_serial_executor` proves serialization rather than episode coalescing; `Value_date_rollover_is_fenced_through_the_same_serial_recovery_owner` covers rollover; `DatasetWorkerManifestIntegrationTests.Reset_and_forced_replacement_restore_latest_manifest_and_preserve_other_dataset_readers` exercises real synthetic child replacement; `SupervisedDatabentoHardRecoveryRuntimeTests` and `RealtimeTickPublisherRecoveryTests` exercise unsafe NATS-send isolation in the new isolated path. These passing tests do not yet constitute retained failing-before-change characterizations for all six DHR-00 failure cases (PostgreSQL timeout, noncooperative NATS send, publisher stop failure, simultaneous callers, failed third attempt, actor restart).

`DatabentoHardRecoveryBaselineTests.Successful_synthetic_worker_replacement_records_elapsed_time_and_exact_process_ownership` is a real synthetic child-process timing baseline. Its focused run passed on 2026-09-30 and measured **589.2 ms** for replacement (old PID **44572**, new PID **18608**, distinct generations), including admission and cleanup assertions. This is one synthetic observation, not a production latency target or distribution. DHR-00 remains open pending complete failing-characterization evidence.

`DatabentoHardRecoveryBaselineTests.Legacy_hard_reset_waits_for_a_hung_PostgreSql_observation_before_worker_teardown` characterizes the current failure: a held observation append prevents the legacy watchdog from reaching worker stop. The test releases the hold by cancellation. It passed in the same focused run (2/2 tests), but is not proof that the new production path is isolated.

Remaining DHR-00 characterization gaps: explicit before-change tests for publisher-stop failure and simultaneous hard-reset callers (serialization alone does not establish coalescing); noncooperative NATS-send evidence specific to the current production path; third-failed-attempt terminal behavior at the API boundary; and actor restart/progress following a reset. Existing unit tests cover nearby mechanics but not these complete failure scenarios. Do not close DHR-00 based on the timing result alone.

Follow-up DHR-00 characterization on 2026-09-30: `DatabentoHardRecoveryBaselineTests.Legacy_simultaneous_hard_reset_callers_are_serialized_but_each_runs_a_separate_episode` held the first stop while issuing a second request and observed **six** start attempts, not one coalesced three-attempt episode; the focused baseline run passed **3/3** and measured another synthetic replacement at **580.0 ms**. Existing `SupervisedHostPublisherLifecycleTests.Noncooperative_actor_send_cannot_block_worker_shutdown_or_allow_unsafe_session_restart` passed and demonstrates that a blocked actor send causes bounded publisher stop failure, worker removal, and rejection of same-host restart. `DatabentoResiliencyTests.Exhausted_core_failure_runs_exactly_three_serial_recovery_attempts_and_latches_red` passed; the current watchdog latches Failed after three attempts but does **not** initiate API shutdown. These two focused tests passed **2/2**. `SupervisorRecoveryReconciliationTests` passed **4/4**, demonstrating isolated actor/projector-owner restart and health reconciliation, not end-to-end progress after a live Databento reset.

DHR-00 remains open at the production boundary: the noncooperative-send test is a synthetic actor-producer fault, not a controlled production NATS outage; the fatal child-process tests exercise the isolated shutdown component, not the existing watchdog-to-API route; and no test yet combines an actual Databento reset with subsequent business-actor/projector progress. Such evidence must be gathered through the later integration and supervised-live gates, without fault injection into an active trading API.

- `DatabentoMarketDataWatchdogService.RecoverAsync` already limits one invocation to three attempts, but `RecordAsync` runs before and during attempts and can involve PostgreSQL and NATS status publication. Exhaustion sets Failed and returns; it does not request API shutdown.
- `StartAndQualifyAsync` calls `PrepareContractsAsync`, which reaches database backed contract reconciliation. Local Databento health is not isolated from this dependency.
- `SupervisedDatabentoLifecycleRuntime.StartAsync` starts the host publisher before child workers. `StopOwnedResourcesAsync` waits on publisher stop and latches `publisherStopFailed`, preventing a later supervised session.
- `RealtimePublicationRecoveryService` uses a separate five second retry delay and can issue a later reset request after failure. It must join one episode and stop after terminal classification.
- `DatasetDesiredSubscriptionRegistry` holds immutable per dataset manifests. Its new `CaptureRecoverySet` operation atomically validates a complete required dataset set for one value date without I/O.
- `DatasetWorkerAdmissionRegistry` fences dataset generations. `DatasetWorkerProcessRecoveryService.StartOwnedAsync` currently admits during startup; candidate admission must be deferred until local qualification. Its `StopAllAsync` can wait without a deadline on entry lifecycle, so hard reset cannot reuse it unchanged.
- `Program.cs` has normal host and supervisor shutdown and a generic startup exception/Serilog flush boundary. It lacks a direct fatal recovery report, fixed graceful deadline, and forced nonzero exit guard.

## Qualification boundary

The new hard runtime, soft gate, holding buffer, and fatal shutdown coordinator are not yet connected to the production reset callers or ingress/publication boundaries. These isolated tests do not establish a safe live recovery path. Automatic fatal shutdown must remain disabled until the child-process, full fault-matrix, supervised live, and production-readiness gates pass. A controlled live NATS outage or worker loss must not be injected into an active trading API without an operator-observed qualification window.

The child-process exit-code gate and actual Development infrastructure probe run are now covered. The NATS probe proves an isolated JetStream publish acknowledgement. The new Supervisor canary proves NATS command to JetStream event to a side-effect-free projector for an exact candidate identity while market-data admission stays fenced. It does not prove that the actual market-data publisher and all required business projectors advance, nor does it provide privileged projector lifecycle reconciliation. DHR-07 therefore remains open.

## Confirmed generation-isolation boundary

`DatasetPublicationIngress` validates the worker generation and passes its cancellation token into `TickAggregationEventPublisher`. That publisher can have a `NonCooperativeSend`: its underlying `IActorProducer.SendAsync` task may ignore cancellation and finish after the old generation is fenced. The publisher deliberately latches `uncontained` and rejects a new session. Realtime source events now carry `IRealtimeSourceGeneration`, which is copied to NATS headers, and actor intake checks `IRealtimeSourceAdmission`. This protects tagged actor intake, but it is not yet a measured candidate publisher-to-business-projector progress proof. A late uncontained send still cannot be treated as safe solely because its task eventually completes.

The design's immediate terminal rule for an unisolatable old generation resolves this conservatively: a non-cooperative NATS send is an unsafe-isolation failure, not a retryable hard attempt, including after its send task completes. The isolated hard runtime refuses to start candidate workers in this state and rechecks at containment and qualification boundaries. The bounded publisher itself refuses same-process restart after this failure. The full API shutdown is not yet wired, so no production hard-reset caller has switched to this runtime. A future enhancement could propagate admission epoch through every affected NATS event and consumer to permit safe publisher replacement, but that is not assumed here.

## DHR-07 canary decision and remaining isolation boundary

The operator approved the dedicated, side-effect-free Supervisor canary route. It is implemented and passed the isolated end-to-end integration test. Its result is now explicitly scoped `SupervisorControlPlane` and cannot qualify market-data admission. Privileged Supervisor reconciliation now covers owned actor and projector-owner components with per-component results, but actual market-data actor/projector progress remains unproved. A realtime NATS send can remain non-cooperative after fencing; the isolated hard runtime safely classifies this as unrecoverable before launching a candidate. Production caller migration and automatic terminal shutdown must remain off until actual-path proof and all qualification gates pass.
