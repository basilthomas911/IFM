# Event-log-authoritative read projections ? implementation status

Date: 2026-10-11. Status: **implementation in progress; financial approval resolved; not system-wide complete**.

## Required convention

The event log is the authoritative source for business state. A source event must contain the complete accepted facts needed to rebuild its read tables, including resolved amounts, rule/account versions, generated identifiers, source references, timestamps and derived state effects. A receipt/hash alone is insufficient. Required business event and projection writes remain in one PostgreSQL transaction.

Reconstruction applies recorded facts. It does not recalculate prices, consult current admission rules, call a broker, send commands, republish market marks, or repeat backup jobs. Direct realtime observations and disposable trade-plan snapshots retain the previously agreed exceptions; their behavior is not silently changed by this work.

## Implemented and verified

- Ledger single and batch completion events now emit schema version 2 and additive numeric key 16, `LedgerProjectionFacts`. Previously published keys are unchanged.
- Facts include full posting input, exact resolved debit/credit lines and account versions, generated transaction/journal/obligation IDs, rule identity/version, funding cash paid, and the accepted overdrawn effect.
- `LedgerFinancialProjection` reconstructs ledger transactions, journals/entries, balances, withdrawal encumbrances, source deduplication records, valuation marks, funding receipts and operation/posting receipts. Its checkpoint commits with the reconstructed mutations. Duplicate application does not repost balances.
- Normal posting and rebuilding share journal-line/balance persistence and canonical UTC payload JSON. Other ledger writes still have separate normal/reconstruction orchestration; consolidation is outstanding.
- `EventProjectionDescriptor.WithReadModelRebuild` separates the audited materialization action from live workflow effects.
- `ReadProjectionRebuilder` uses only explicit rebuild actions and refuses live-action fallback. The caller must provide persisted source events in ascending order from a stable, quiesced source cut and owns the isolated target/reset procedure. Sequence IDs alone are not a safe online commit cursor.
- Explicit actions registered for Trade Order, Order Execution, Broker Order read state, Futures Trade, Option Trade, Futures/Vertical Spread/Iron Condor position history and routing, and Iron Condor monitoring limits. These actions bypass commands, broker calls and live plan notifications.

## Approved financial continuation

User approval covers configuration source facts, the remaining financial refactor and host registration.

- Configuration events now carry the full accepted book, configuration request, migration state and the accepted reconciliation result. Reconstruction restores these facts without re-running qualification or reconciliation decisions.
- Reservation, consumption and lifecycle events record exact usage deltas. Normal writes and reconstruction share the same rounding/whole-position-slot calculation and mutation helper.
- Emulator events retain the complete accepted admission request. Reconstruction restores its local record without submitting an order.
- Portfolio/Fund authority effects append a `FinancialAuthoritySnapshotEvent` in the same transaction as the originating event and authority mutation. This records the accepted book, epoch, operating state and exact before/after financial revision.
- Financial rebuild services are registered with the host. General ledger, configuration, capacity lifecycle and emulator projectors expose explicit materialization-only actions. The dedicated financial rebuilder also handles Function completion sources.
- `FinancialEventLogReader` reads bounded pages directly from event-log bytes. It does not depend on operation receipts or other read tables. An explicitly quiesced cut and selected Portfolio IDs are required.
- Accounting export preparation/delivery outcomes and broker accounting intent capture now have complete source events and reconstruction methods. The exact captured command bytes are retained; reconstruction does not dispatch accounting commands or deliver exports. Verified by the 42-test financial suite; export and intent round trips are included.
- Reconstructed financial state and each source checkpoint commit atomically. Financial core events require their recorded revision order; operational export/intent events do not advance financial authority.
