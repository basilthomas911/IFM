## Method and limits

Inventory includes every nonignored working-tree C# file in UI.Net.ViewModels and UI.Net.Models, including contracts, helpers, nested types and journals. Production and test C# files are scanned for type and extension-method identifier references, with comments and string literals excluded. Counts below are source files, not runtime screens or class counts. Build output is excluded; new untracked application sources are included. Reflection, dependency injection, overload resolution, generic resolution, same-name types and method-level reachability require manual reconciliation. A reference is evidence of a dependency, not proof that a user executed the path. A missing direct bridge reference does not establish dead code.

The [CSV](IFM-Windows-Rust-UI-Model-Inventory-2026-10-23.csv) records all discovered production/test reference locations and a target disposition for each file. Rows without a proven entry path remain review items; none are silently excluded from migration.

The [supporting dependency CSV](IFM-Windows-Rust-UI-Dependency-Inventory-2026-10-23.csv) inventories 199 service, consumer, composition, API-client and bridge files, including models declared outside the two primary model projects. Backend/shared wire DTOs remain backend contracts; the implementation operation registry must close their transitive wire dependencies.

The [backend boundary audit](IFM-Rust-UI-Backend-Boundary-Audit-2026-10-23.md) and its working-tree checklist refine these file-level dispositions with current Rust method/branch evidence. The current Rust UI is the standalone behavior baseline; unused WinForms paths do not require new backend equivalents.

```powershell
python scripts/UI/Rust/Update-RustUiModelInventory.py --date 2026-10-23
```
